# Kiko-Bot

Kiko-Bot is a 6-DOF robot arm. This repo has everything for it:

- the **MuJoCo simulation** of the arm and a pick-and-place scene,
- a **teleoperation controller** (keyboard or gamepad, Cartesian IK),
- the **hardware bridge** that drives the real servos,
- a **LeRobot plugin** to record demonstrations, train a policy and test it in sim.

## 1. Repository layout

| Path | What's in it |
|---|---|
| `models/` | MuJoCo (MJCF) files. `robot.xml` is generated by onshape-to-robot; `extras.xml` holds hand-written additions that are spliced back in after each re-export. |
| `models/scene.xml` | The arm on its own. |
| `models/pick_place_scene.xml` | The arm, a table, a red cube, a green place pad and the `record` camera. |
| `kikobot/sim/controller.py` | Cartesian IK teleop controller. |
| `kikobot/sim/training_env.py` | The pick-and-place scene with randomised cube positions. |
| `kikobot/sim/viewer.py` | A simple viewer with one slider per joint. |
| `kikobot/hardware/scan_ids.py` | Scans the servo bus and lists the servo IDs it finds. |
| `kikobot/hardware/joint_gui.py` | Tk GUI for tuning each servo. |
| `kikobot/hardware/physical_controller.py` | Mirrors the sim's joint targets onto the real arm. |
| `lerobot_integration/` | The LeRobot plugin (`kikobot_sim` robot and `kikobot_teleop` teleoperator). |
| `lerobot_integration/scripts/record.py` | Records demonstrations into a LeRobot dataset. |
| `lerobot_integration/scripts/evaluate.py` | Runs a trained policy in sim and reports its success rate. |

Every script finds the model files through `kikobot.MODELS_DIR`, so you can run it from any folder.

## 2. Quick start: simulation only

You need **Python 3.12 or newer**. Install only the extras you need:

```bash
pip install -e .                  # simulation only
pip install -e ".[teleop,video]"  # + gamepad support and MP4 recording
pip install -e ".[hardware,gui]"  # + real arm and servo tuning GUI
```

Then run any of these:

```bash
python -m kikobot.sim.controller      # drive the arm with keyboard/gamepad
python -m kikobot.sim.training_env    # pick-and-place scene, random cube spawns
python -m kikobot.sim.viewer          # joint slider viewer
python -m kikobot.hardware.scan_ids   # find servos on the bus (real arm)
```

> **macOS:** the interactive MuJoCo window needs `mjpython` instead of
> `python` (for example `mjpython -m kikobot.sim.controller`). Windows and Linux
> use plain `python`.

## 3. Controls

### Keyboard (same in the standalone controller and in LeRobot)

| Key | Action |
|---|---|
| `↑` `↓` `←` `→` | Move the gripper forward / back / left / right |
| `Q` / `E` | Move the gripper up / down |
| `R` / `F` | Rotate wrist joint J5 + / − |
| `Z` / `X` | Rotate wrist joint J6 + / − |
| `O` / `P` | Open / close the jaws (hold; release as soon as they grip) |
| `C` | Centre J5 and J6 *(standalone controller only)* |
| `H` | Return to the ready pose *(standalone controller only)* |

### Gamepad (Xbox-style)

The gamepad mapping depends on which program you're running:

| Control | Standalone controller (`kikobot.sim.controller`) | LeRobot (`--backend gamepad`) |
|---|---|---|
| Left stick | Move in X/Y | Move in X/Y |
| Right stick | J5 (left/right) and J6 (up/down) | Up/down moves in Z; left/right does nothing |
| LT / RT | Move down / up in Z | Open / close the jaws |
| LB / RB | Open / close the jaws | Rotate J6 + / − |
| A | Centre J5 and J6 | — |

In LeRobot, J5 can't be controlled from the gamepad. Use the keyboard if you need it.

### While recording (`record.py`)

| Key | Action |
|---|---|
| `→` or `n` | Save this episode and move to the next one |
| `←` or `r` | Discard this episode and record it again |
| `Esc` or `q` | Stop recording and save the dataset |

## 4. LeRobot: record, train, evaluate

The `lerobot_integration/` package makes the MuJoCo scene look like a real
robot to [LeRobot](https://github.com/huggingface/lerobot). That lets you use
LeRobot's normal workflow:

```
teleoperate  →  record demos  →  train a policy  →  evaluate it in sim
```

The simulation runs inside the same Python process as LeRobot, so **LeRobot,
MuJoCo and this repo must all be installed in one Python environment**.

### 4.1 Install

LeRobot 0.6.2 isn't on PyPI, so clone it and install it from source.

**Windows (PowerShell)**

```powershell
git clone https://github.com/huggingface/lerobot.git $HOME\lerobot
cd $HOME\lerobot
py -3.12 -m venv .venv

# NVIDIA GPU only: install CUDA torch FIRST, or pip picks the CPU version.
.venv\Scripts\pip install torch torchvision --index-url https://download.pytorch.org/whl/cu124

.venv\Scripts\pip install -e ".[core_scripts,training]"
.venv\Scripts\pip install mujoco glfw

cd C:\path\to\KikoBot
$HOME\lerobot\.venv\Scripts\pip install -e . -e lerobot_integration
```

**macOS / Linux**

```bash
git clone https://github.com/huggingface/lerobot.git ~/lerobot
cd ~/lerobot
python3.12 -m venv .venv
.venv/bin/pip install -e ".[core_scripts,training]"
.venv/bin/pip install mujoco glfw

cd /path/to/KikoBot
~/lerobot/.venv/bin/pip install -e . -e lerobot_integration
```

What the extras do:

- `core_scripts` adds dataset writing, keyboard capture (`pynput`) and the rerun viewer.
- `training` adds `accelerate`, which `lerobot-train` needs.

**About `$V` in the commands below:** `V` stands for the venv's scripts folder.

| OS | Set it with |
|---|---|
| Windows (PowerShell) | `$V = "$HOME\lerobot\.venv\Scripts"`, then run tools as `& "$V\python.exe" ...` |
| macOS / Linux | `V=~/lerobot/.venv/bin`, then run tools as `$V/python ...` |

The examples below use macOS/Linux syntax. On Windows, replace each trailing
`\` with a backtick (`` ` ``) and write `$V/lerobot-train` as `& "$V\lerobot-train.exe"`.

### 4.2 Check the install

**Don't skip this step.** If the plugin fails to import, LeRobot ignores the
error and the robot type just isn't available, so you'd only find out later.

```bash
$V/python -c "
import lerobot.scripts.lerobot_record as rec
from lerobot.robots import RobotConfig
rec.register_third_party_plugins()
print('kikobot_sim' in RobotConfig.get_known_choices())"
```

It must print `True`. Also check that the GPU is visible (Windows/NVIDIA):

```bash
$V/python -c "import torch; print(torch.cuda.is_available())"   # must print True
```

### 4.3 Test the pipeline end to end

Before spending an hour recording, run a quick test of the whole chain:
record 2 short episodes, train for 2000 steps, then evaluate. The policy will
be useless, but if each step runs, everything is wired up correctly.
`--backend scripted` moves the arm automatically, so you don't need to drive it.

```bash
$V/python lerobot_integration/scripts/record.py --episodes 2 --episode-time 6 \
  --backend scripted --no-display --no-sound \
  --repo-id local/smoke --root datasets/smoke

$V/lerobot-train --dataset.repo_id=local/smoke --dataset.root=datasets/smoke \
  --policy.type=act --policy.device=cuda --policy.push_to_hub=false \
  --steps=2000 --batch_size=8 \
  --output_dir=outputs/train/smoke --wandb.enable=false

$V/python lerobot_integration/scripts/evaluate.py \
  --policy outputs/train/smoke/checkpoints/last/pretrained_model --episodes 2
```

### 4.4 Teleoperate

This just drives the arm without recording, so you can check that the controls feel right:

```bash
$V/lerobot-teleoperate --robot.type=kikobot_sim --teleop.type=kikobot_teleop --display_data=true
```

Add `--teleop.backend=gamepad` to use a gamepad. `--display_data=true` opens the
rerun viewer so you can see the camera.

### 4.5 Record demonstrations

```bash
$V/python lerobot_integration/scripts/record.py --episodes 50 --episode-time 40
```

Each episode resets the scene with a new random cube position. Do the
pick-and-place, then press `→` to save (see [controls](#while-recording-recordpy)).

`record.py` options:

| Option | Default | Meaning |
|---|---|---|
| `--episodes` | `50` | Number of episodes to record |
| `--episode-time` | `40` | Maximum seconds per episode |
| `--reset-time` | `5` | Seconds between episodes (not recorded) |
| `--backend` | `keyboard` | `keyboard`, `gamepad` or `scripted` |
| `--repo-id` | `local/kikobot_pickplace` | Dataset name (just a label; nothing is uploaded) |
| `--root` | `datasets/kikobot_pickplace` | Folder the dataset is saved to |
| `--task` | `Pick up the red cube and place it on the green pad` | Task description stored with each episode |
| `--fps` | `30` | Control and recording rate |
| `--width` / `--height` | `640` / `480` | Camera resolution (max 1280 × 720) |
| `--seed` | random | Seed for the cube spawn positions |
| `--viewer` | off | Open a native MuJoCo window (smoother than rerun) |
| `--no-display` | off | Don't open the rerun viewer |
| `--no-sound` | off | Turn off spoken prompts (recommended on Windows) |

**Use a new `--root` folder for each recording.** The script creates a new
dataset each time and won't add to an existing one:

```bash
$V/python lerobot_integration/scripts/record.py --episodes 50 \
  --repo-id local/kikobot_run2 --root datasets/kikobot_run2
```

To replay a recorded dataset:

```bash
$V/lerobot-dataset-viz --repo-id=local/kikobot_pickplace --root=datasets/kikobot_pickplace
```

### 4.6 Train a policy (fully local)

```bash
$V/lerobot-train --dataset.repo_id=local/kikobot_pickplace \
  --dataset.root=datasets/kikobot_pickplace \
  --policy.type=act --policy.device=cuda --policy.push_to_hub=false \
  --steps=60000 --batch_size=16 \
  --output_dir=outputs/train/kikobot_act --wandb.enable=false
```

Some of these flags are needed to keep training off the Hugging Face Hub:

| Flag | Why it's needed |
|---|---|
| `--policy.push_to_hub=false` | **Required.** Without it, training fails with `'repo_id' argument missing` because LeRobot tries to upload the model. |
| `--dataset.repo_id=local/...` | Just a name. `--dataset.root` points to the local folder, so nothing is downloaded. |
| `--wandb.enable=false` | Turns off Weights & Biases logging. |
| `--policy.device` | `cuda` on an NVIDIA GPU, `mps` on Apple Silicon (slower), `cpu` as a last resort. |

Other notes:

- **No internet at all?** Set `HF_HUB_OFFLINE=1` first (`$env:HF_HUB_OFFLINE=1` in
  PowerShell). On its first run, ACT downloads an ImageNet ResNet from
  torchvision, so run it once while online, or copy over the
  `~/.cache/torch/hub` folder from another machine.
- **Out of GPU memory?** Lower `--batch_size` to 8.
- **`--output_dir` must not already exist.** Use a new name for each run, or add
  `--resume=true` to continue a stopped run.
- Checkpoints are saved in `outputs/train/<run>/checkpoints/`. The latest one is
  in `checkpoints/last/pretrained_model`.

### 4.7 Evaluate the policy

```bash
$V/python lerobot_integration/scripts/evaluate.py \
  --policy outputs/train/kikobot_act/checkpoints/last/pretrained_model --episodes 20
```

`evaluate.py` options:

| Option | Default | Meaning |
|---|---|---|
| `--policy` | *(required)* | Path to a `pretrained_model` folder |
| `--episodes` | `20` | Number of test episodes |
| `--episode-time` | `40` | Maximum seconds per episode |
| `--device` | the policy's own | Override, e.g. `cpu` |
| `--seed` | `0` | Seed for cube spawns (keep it fixed to compare policies fairly) |
| `--task` / `--fps` | same as recording | Should match what you recorded with |

### 4.8 Moving data between machines

Datasets and trained models are plain folders, so you can just copy them:

1. Record on whichever machine you teleoperate from.
2. Copy `datasets/kikobot_pickplace/` to the GPU machine and train there.
3. Copy `outputs/train/<run>/checkpoints/last/pretrained_model/` back and evaluate.

## 5. Available policies

Choose one with `--policy.type=<name>`:

| Policy | What it is | For this project |
|---|---|---|
| `act` | Action Chunking Transformer | **Start here.** Trains from scratch on ~50 demos, fast, and fits on one GPU. |
| `diffusion` | Diffusion Policy | Good second baseline. Slower to train and run than ACT. |
| `vqbet` | VQ-BeT | Works, but needs more tuning. |
| `smolvla` | Small vision-language-action model (~450M params) | Fine-tune with `--policy.path=lerobot/smolvla_base` instead of `--policy.type`. Needs about 8 GB+ of VRAM and downloads its weights on the first run. |
| `pi0` / `pi05` | Large VLA models | Need 24 GB+ of VRAM. |
| `tdmpc`, `sac` | Reinforcement learning | Need rewards or online interaction, so they aren't suitable for training from recorded demos. |

To see every policy your installed LeRobot version supports, run `$V/lerobot-train --help`.

## 6. Dataset format

| | Contents |
|---|---|
| **Observations** | 6 joint angles (`.pos`), jaw opening (`gripper.pos`), end-effector position (`ee_x/y/z.pos`) = 10 floats, plus the `record` camera image (640 × 480 by default) |
| **Actions** | Absolute commanded targets: end-effector position (`ee_x/y/z.pos`), the two wrist joints (`j5.pos`, `j6.pos`) and the jaws (`gripper.pos`) = 6 floats. The sim's IK turns the end-effector target into joint motion. |

The `.pos` suffix is required. `lerobot-rollout` ignores any feature
without a `.pos`/`.vel` suffix, which would leave the policy with no actions.

## 7. Platform notes

| | Windows | macOS |
|---|---|---|
| Interactive MuJoCo window | `python` | needs `mjpython` |
| Recording (offscreen rendering) | `python` | `python` |
| Keyboard teleop | works as-is | needs Accessibility permission (below) |
| Spoken prompts while recording | slow (starts PowerShell each time); use `--no-sound` | uses `say` |
| GPU training | `--policy.device=cuda` | `--policy.device=mps` |

**macOS keyboard permission:** go to System Settings → Privacy & Security →
Accessibility and enable your terminal app. Without it, keyboard capture
starts but receives no key presses, so the arm never moves.

## 8. Troubleshooting

| Problem | Fix |
|---|---|
| `'repo_id' argument missing` when training | Add `--policy.push_to_hub=false`. |
| `kikobot_sim` isn't a valid robot type | The plugin didn't load. Run the check in [4.2](#42-check-the-install) and make sure everything is in the same venv. |
| `torch.cuda.is_available()` is `False` | The CPU build of torch was installed. Reinstall with the CUDA command in [4.1](#41-install). |
| Arm doesn't move with the keyboard (macOS) | Grant Accessibility permission (see [7](#7-platform-notes)). |
| `No gamepad detected` | Connect the controller before starting. Only the first controller (`JOYSTICK_1`) is read. |
| Recording fails because the folder exists | Use a new `--root` for each recording. |
| Training fails because the output folder exists | Use a new `--output_dir`, or add `--resume=true`. |
| CUDA out of memory | Lower `--batch_size`. |
