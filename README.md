# Kiko-Bot

A 6-DOF robot arm: the MuJoCo model, the Cartesian teleoperation stack, and the
hardware bridge to the physical servos.

## Layout

| Path | What it is |
|---|---|
| `models/` | MJCF. `robot.xml` is generated by onshape-to-robot; `extras.xml` is spliced back in on re-export. Scenes: `scene.xml` (arm only), `pick_place_scene.xml` (arm + table + cube + place pad + `record` camera). |
| `kikobot/sim/` | `controller.py` — Cartesian IK teleop. `training_env.py` — the pick-and-place scene with randomised spawns. `viewer.py` — a bare slider viewer. |
| `kikobot/hardware/` | `scan_ids.py` — bus scan. `joint_gui.py` — per-servo Tk tuning GUI. `physical_controller.py` — mirrors sim joint targets onto the real arm. |
| `docs/controls.md` | Keyboard and gamepad reference, and how the IK works. |
| `lerobot_integration/` | The LeRobot plugin (`kikobot_sim` robot + `kikobot_teleop` teleoperator) and the record/evaluate scripts. |
| `archive/` | Superseded experiments, kept for the thesis write-up. |

## Install

```bash
pip install -e .                 # sim only
pip install -e ".[teleop,video]" # + gamepad and MP4 capture
pip install -e ".[hardware,gui]" # + physical arm
```

## Run

```bash
python -m kikobot.sim.controller      # teleop the arm (scene.xml)
python -m kikobot.sim.training_env    # pick-and-place scene with randomised spawns
python -m kikobot.sim.viewer          # slider viewer
python -m kikobot.hardware.scan_ids   # scan the servo bus
```

On macOS the interactive MuJoCo viewer needs `mjpython` instead of `python`
(`mujoco.viewer.launch_passive` must own the main thread). Offscreen rendering
does not.

Every entry point resolves the MJCF through `kikobot.MODELS_DIR`, so it runs
from any working directory.

## Controls

See [`docs/controls.md`](docs/controls.md). In short: arrows move the gripper in
XY, `Q`/`E` move it in Z, `R`/`F` and `Z`/`X` rotate the wrist, `O`/`P` work the
jaws, `H` returns to the ready pose.

## LeRobot integration

`lerobot_integration/` exposes the MuJoCo scene to
[LeRobot](https://github.com/huggingface/lerobot) as a `Robot` (`kikobot_sim`)
and a `Teleoperator` (`kikobot_teleop`): teleoperate the arm, record a dataset,
train a policy, and score it back in the same sim.

The sim runs in-process — `send_action` steps MuJoCo directly — so everything
needs to live in **one** Python environment.

### Setup

LeRobot is not on PyPI in the version this targets (0.6.2), so clone it. Both
platforms need Python 3.12 or newer.

**macOS / Linux**

```bash
git clone https://github.com/huggingface/lerobot.git ~/lerobot
cd ~/lerobot
python3.12 -m venv .venv
.venv/bin/pip install -e ".[core_scripts,training]"
.venv/bin/pip install mujoco glfw

cd /path/to/KikoBot
~/lerobot/.venv/bin/pip install -e . -e lerobot_integration
```

**Windows (PowerShell)**

```powershell
git clone https://github.com/huggingface/lerobot.git $HOME\lerobot
cd $HOME\lerobot
py -3.12 -m venv .venv
.venv\Scripts\pip install -e ".[core_scripts,training]"
.venv\Scripts\pip install mujoco glfw

cd C:\path\to\KikoBot
$HOME\lerobot\.venv\Scripts\pip install -e . -e lerobot_integration
```

For CUDA training on Windows, install the matching torch build *before* the
line above, otherwise pip resolves the CPU wheel:

```powershell
.venv\Scripts\pip install torch torchvision --index-url https://download.pytorch.org/whl/cu124
```

`core_scripts` pulls in dataset writing, pynput and the rerun viewer;
`training` adds accelerate, which `lerobot-train` requires.

### Check the setup

One interpreter must have everything, and LeRobot must have found the plugin:

```bash
# macOS/Linux: ~/lerobot/.venv/bin/python     Windows: $HOME\lerobot\.venv\Scripts\python
python -c "
import lerobot.scripts.lerobot_record as rec
from lerobot.robots import RobotConfig
rec.register_third_party_plugins()
print('kikobot_sim' in RobotConfig.get_known_choices())"   # must print True
```

That check is not optional: LeRobot swallows plugin import errors, so a broken
plugin disappears silently instead of failing.

### Platform notes

| | macOS | Windows |
|---|---|---|
| Interactive MuJoCo viewer | needs `mjpython` | plain `python` |
| Offscreen rendering (what recording uses) | plain `python` | plain `python` |
| Keyboard teleop | needs Accessibility permission | works as-is |
| Spoken episode prompts | `say` | spawns PowerShell per episode — use `--no-sound` |

On macOS, grant your terminal Accessibility permission (System Settings →
Privacy & Security → Accessibility) or `pynput` starts but captures nothing
and the arm never moves. Windows needs no equivalent.

### Run

Substitute `V` for your venv: `~/lerobot/.venv/bin` on macOS/Linux,
`$HOME\lerobot\.venv\Scripts` on Windows (and drop the `$` prefix when
calling it from PowerShell).

```bash
V=~/lerobot/.venv/bin

# 1. Teleoperate, nothing recorded -- check the controls feel right first.
$V/lerobot-teleoperate --robot.type=kikobot_sim --teleop.type=kikobot_teleop --display_data=true

# 2. Record demonstrations. --backend gamepad also works.
$V/python lerobot_integration/scripts/record.py --episodes 50 --episode-time 40

# 3. Train ACT. cuda on the Windows box; mps on the Mac works but is slower.
$V/lerobot-train --dataset.repo_id=local/kikobot_pickplace \
  --dataset.root=datasets/kikobot_pickplace \
  --policy.type=act --policy.device=cuda --policy.push_to_hub=false \
  --steps=60000 --batch_size=16 \
  --output_dir=outputs/train/kikobot_act --wandb.enable=false

# 4. Score the trained policy in sim.
$V/python lerobot_integration/scripts/evaluate.py \
  --policy outputs/train/kikobot_act/checkpoints/last/pretrained_model --episodes 20
```

Choose the dataset name with `--repo-id` and its local directory with `--root`.
For example, to record a separate dataset rather than use the default
`local/kikobot_pickplace` / `datasets/kikobot_pickplace`:

```powershell
& "$V\python.exe" ".\lerobot_integration\scripts\record.py" `
  --episodes 50 --episode-time 40 `
  --repo-id local/my_kikobot_data --root datasets/my_kikobot_data
```

The recording script creates a new dataset at `--root`; use a new directory
for each recording rather than pointing it at an existing dataset.

With `--backend gamepad`, the left stick controls XY (up/down is inverted from
the previous mapping), the right stick's vertical axis controls Z, and LT/RT
control the gripper (their directions are inverted from the previous mapping).

While recording: `→`/`n` saves the episode, `←`/`r` re-records it, `esc`/`q`
stops. `--display_data=true` opens rerun, which is how you watch the arm
without `mjpython`. Inspect a finished dataset with
`$V/lerobot-dataset-viz --repo-id=local/kikobot_pickplace --root=datasets/kikobot_pickplace`.

The dataset directory is self-contained, so the intended split works by plain
copy: record on whichever machine you teleoperate from, copy
`datasets/kikobot_pickplace/` to the Windows box, train there with
`--policy.device=cuda`, then copy `checkpoints/last/pretrained_model` back and
evaluate in sim.

### Prove the loop first

Before committing to a 50-episode session, run the whole chain small — two
6-second episodes, 2000 training steps, then evaluate. The policy will be
useless, but it proves the schema, the plugin, video encoding and the eval
path. `--backend scripted` drives a canned motion so this needs nobody at the
keyboard:

```bash
$V/python lerobot_integration/scripts/record.py --episodes 2 --episode-time 6 \
  --backend scripted --no-display --repo-id local/smoke --root /tmp/smoke
```

### Data layout

Observations are the six joint angles, the jaw opening and the absolute
end-effector position (10 floats) plus the `record` camera at 320x240. Actions
are per-tick end-effector deltas, the two wrist axes and the jaws (6 floats).

The `.pos`/`.vel` suffixes on feature names are required — `lerobot-rollout`
drops any feature without one, which would leave an empty action space.
